\# Project instructions



\- Read docs/SRS.md and docs/design.md before making architectural changes.

\- SRS defines product requirements.

\- design.md defines the approved architecture and technical decisions.

\- Do not silently change requirements or architecture.

\- Add or update tests for every implementation change.

\- Run formatting, typecheck, tests and build before reporting completion.

\- Never commit secrets or modify production resources.

\- Report inconsistencies between SRS and design.md to the coordinator.
